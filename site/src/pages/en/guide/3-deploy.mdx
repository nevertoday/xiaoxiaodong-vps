## What this step is

Configure the server you bought in step 2: install the nodes, get a <Term k="证书" text="certificate" />, install the AI API and harden security. Everything happens on your own computer; you never log in to the server. Both routes do exactly the same thing; only who types differs.

Afterwards:

- `ssh your-name` logs you in without a password (using a <Term k="密钥" text="key" /> instead);
- your desktop has a new file `我的服务器-your-name-订阅和账号.md` (or `my-server-your-name-subscriptions-and-accounts-en.md` if you ask for English) with the subscription URLs and the panel and AI API logins.

**Pick a name first**, such as `bwg` or `la1`: letters, digits, dots and hyphens only, starting with a letter. From then on, `ssh bwg` logs you in.

### 1. Send this message to the AI

Open Codex from step 1 (desktop app or `codex` in the terminal; any other AI tool that passed the test in step 1 works too), copy the message below, **fill in your details**, and send it:

<Copy id="prompt" title="Message for the AI" code={`Please configure my new server with the "xiaoxiaodong VPS" setup.

Setup: https://github.com/nevertoday/xiaoxiaodong-vps
Download the project first, read skills/xiaoxiaodong-vps/SKILL.md in full,
and follow its steps and rules strictly, using the project's scripts for deployment and verification.
If you can't run commands on my computer, tell me so directly instead of having me type commands one by one.
Please talk to me in English and save the login file in English.

My server:
- IP:
- Login: initial password (let me type it myself; don't ask me to send it in the chat)
- SSH user and port: default
- Name I want to use to log in: bwg
- BandwagonHost VEID and API Key (for official traffic usage; delete this line if it isn't BandwagonHost):`} />

What to change:

- **IP**: the server IP from step 2.
- **Login**: if the provider gave you a key file, change it to `key file: path` (a zip works too).
- **SSH user and port**: if they aren't root and 22, replace "default" with the real values.
- **Name**: replace `bwg` with your chosen name.
- **BandwagonHost**: fill in the VEID and API key on the last line (on the API page in KiwiVM's left menu — [how to find them](/en/howto/traffic-and-ip/)). Your apps then read the traffic quota, usage and reset day straight from BandwagonHost, so 1 TB and 2 TB plans both show correctly. **Not on BandwagonHost? Delete that line**; usage is then shown against 1000 GB a month.

### 2. Type the password once in the pop-up box

The AI first tells you a password box is about to appear, then a small window pops up on your computer. Type the server's root password (only dots show — that's normal) and click OK. The password goes straight to the setup script and never enters the chat history.

<Callout type="tip" title="Using the Codex command line?">
The password box pops up there too. If your computer can't show windows (for example a Linux machine you're connected to remotely), the AI gives you a command: run it in the terminal, type the password when asked, then go back and tell it you're done.
</Callout>

<Callout type="no">
Don't paste the password into the chat — wait for the password box.
</Callout>

### 3. Wait for it to finish

Usually about 10 minutes. The AI works stage by stage and reports progress: base setup → certificate → nodes → subscription → AI API → maintenance → verification.

If something goes wrong, the AI fixes it using the setup's troubleshooting notes and reruns that stage. You only answer its questions.

If the AI can't download the project, [download the ZIP](https://github.com/nevertoday/xiaoxiaodong-vps/archive/refs/heads/main.zip) yourself, unzip it, and add "the project is already at: folder path" to the message.

### 0. Open a terminal

All the commands below run in **your own computer's** terminal, not on the server.

- **Mac**: press <kbd class="xxd-kbd">⌘</kbd> + <kbd class="xxd-kbd">Space</kbd>, type "Terminal" and press Enter.
- **Windows**: first download Git for Windows from [git-scm.com](https://git-scm.com/download/win), double-click it and click "Next" through the defaults. Then open **Git Bash** from the Start menu — that window is your "terminal" from here on.

Copy a command in, press Enter and wait for it to finish. A new line ending in `$` or `%` means it's done. Nothing shows on screen while you type a password — that's normal.

Each block below: copy → paste into the terminal → Enter → wait for it to finish, then the next. **Replace `your-IP` and `bwg` with your own.**

<Callout type="warn" title="Use one terminal window throughout">
The later commands run inside the folder you entered in "Download the setup" and use the `R=…` variable. If you close the terminal midway, reopen it and first run <Cmd c="cd xiaoxiaodong-vps/skills/xiaoxiaodong-vps" /> and <Cmd c="R=scripts/local/remote.sh" />, then continue.
</Callout>

### 1. Download the setup

<Copy id="m-clone" lang="bash" title="Download and enter the folder" code={`git clone https://github.com/nevertoday/xiaoxiaodong-vps.git
cd xiaoxiaodong-vps/skills/xiaoxiaodong-vps`} />

The first time you use `git` on a Mac, a pop-up may offer to install the "command line developer tools". Install them, then run the command again.

### 2. Set up passwordless login

<Copy id="m-connect" lang="bash" title="Set up passwordless login (asks for the root password once)" code="bash scripts/local/connect.sh --alias bwg --host your-IP --port 22 --user root --password-prompt" />

If your SSH port isn't 22, change `--port 22`. Seeing `完成：以后用 ssh bwg 登录` ("done: log in with ssh bwg from now on") means it worked — the scripts print messages in Chinese.

### 3. Choose a time zone

Pick by the server's city; you'll use it in the next block:

| Data center | Time zone |
|---|---|
| Los Angeles, San Jose, US West | `America/Los_Angeles` |
| New York, US East | `America/New_York` |
| Hong Kong | `Asia/Hong_Kong` |
| Tokyo | `Asia/Tokyo` |
| Singapore | `Asia/Singapore` |
| Not sure | `Etc/UTC` |

### 4. Run the configuration in order

<Copy id="m-deploy" lang="bash" title="Run block by block (or paste it all)" code={`R=scripts/local/remote.sh
bash $R bwg upload
bash $R bwg init --ip your-IP --alias bwg --timezone America/Los_Angeles
bash $R bwg base
bash $R bwg cert
bash $R bwg xui
bash $R bwg sub
bash $R bwg cliproxy
bash $R bwg maint`} />

Each stage ends with `xxx 完成` ("xxx done"), e.g. `cert 完成`. Apps show traffic against 1000 GB a month by default, with the reset day worked out from the provisioning date. If your plan differs, add `--quota-gb QUOTA --reset-day DAY` to the end of the `init` line (e.g. `--quota-gb 500 --reset-day 1`). On a BandwagonHost server you can instead run `bash $R bwg kiwivm --veid VEID --key-file FILE-CONTAINING-THE-KEY` after `sub`, and the quota, usage and reset day come straight from its dashboard — see [Traffic](/en/howto/traffic-and-ip/).

<Callout type="warn" title="If you see 停止： (stopped)">
When a stage stops, it prints `停止：` ("stopped:") and a reason. Fix the cause and **rerun the same stage** — every stage can be run again. Common causes and fixes: [troubleshooting notes](https://github.com/nevertoday/xiaoxiaodong-vps/blob/main/skills/xiaoxiaodong-vps/references/troubleshooting.md) (in Chinese).
</Callout>

### 5. Verify and save the login info

bash $R bwg save --lang en`} />

## How you know it worked

<Callout type="ok">
The last lines show `验收：34/34 通过` (verification: 34/34 passed — every item PASS), followed by a message that the login file has been saved.
</Callout>

Where the login-info file is:

- On your computer's **desktop** (both Mac and Windows).

The file contains: the Clash subscription URL, the Shadowrocket subscription URL, the 3x-ui panel login and the CLIProxyAPI address and keys. **You'll need the subscription URL in the next step.**

**How to open it**: it's a plain-text file. On Mac, right-click → "Open With" → "TextEdit"; on Windows, right-click → "Open with" → "Notepad". A subscription URL is one long line starting with `https://` — copy the whole line.

<Callout type="no">
This file holds every password and key. Keep it only on your own computer — never post, screenshot or upload it.
</Callout>

## Stuck?

<Q q="The certificate stage failed?">
Most often the provider's "security group" or firewall blocks port 80. Allow TCP 80 in the provider's dashboard and rerun `cert`. The setup never falls back to a self-signed certificate.
</Q>
<Q q="It says the OS isn't supported?">
Only Ubuntu 22.04+ and Debian 12+ are supported. Reinstall as Ubuntu 24.04 from the provider's dashboard — see [Reinstall the OS as Ubuntu](/en/howto/reinstall-os/). The password changes after reinstalling; start again from passwordless login with the new one.
</Q>
<Q q="The password is right, but key login fails?">
Some provider images disable SSH key login by default. Current versions of the scripts turn it back on automatically; if you have an old copy, update the setup and try again.
</Q>
<Q q="One or two verification items FAIL?">
Read the note after the FAIL line, fix it, rerun that stage, then run `verify --full` again. On the AI route, just let the AI handle it.
</Q>
<Q q="After reinstalling the OS, my ssh name won't connect?">
Reinstalling changes the server's identity fingerprint, and sometimes the port. See [Reinstall the OS as Ubuntu](/en/howto/reinstall-os/) for the clean-up commands.
</Q>
